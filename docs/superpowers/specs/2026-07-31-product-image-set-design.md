# 套图处理设计

**日期：** 2026-07-31
**状态：** 初始设计，控件与出图契约已由 `2026-07-31-product-image-set-controls-enhancement-design.md` 取代
**范围：** Electron 桌面应用中的主图、对比图和多场景图生成

> **现行契约：** 本文中关于套图控件、对比图布局和多场景提示词的初始规则不再作为验收依据。以 `2026-07-31-product-image-set-controls-enhancement-design.md` 为准：对比图每张为一个场景的一组 Before/After，可选自动、左右或上下布局；多场景提示词可选，支持单场景、拼图和宫格；三个 Tab 均支持可选正向和反向提示词。

## 1. 背景

Tickpic 当前提供贴纸出图和产品处理，但缺少从同一 SKU 直接生成一组电商用途图片的独立工作区。现有“主图裂变”“场景裂变”依赖不同的输入与输出语义，不能准确表达以下新需求：

- 根据 SKU 自动策划带英文大标题和核心场景的主图。
- 根据 SKU 输出单场景的一组 Before/After 对比图。
- 根据 SKU 输出多张互不重复的适用场景图，提示词可选。

本次增加独立的“套图处理”导航入口和三个独立图片功能，同时复用现有上传、参数、任务、结果与本地存储能力，不改变已有产品处理功能的行为。

## 2. 目标与非目标

### 2.1 目标

1. 在侧边导航“产品处理”之后增加“套图处理”。
2. 套图处理包含“主图”“对比图”“多场景图”三个子 Tab，默认进入“主图”。
3. 每个 Tab 支持上传同一 SKU 的多张参考图。
4. 每个 Tab 支持现有预设图片比例和生成数量选择器，并服从系统最大数量限制。
5. 主图自动生成英文大标题，并同时呈现 SKU 产品和核心场景。
6. 对比图每张输出一个场景的一组 Before/After，布局可自动、左右或上下；Before 不展示 SKU，After 是否展示 SKU 可控制。
7. 多场景图提示词可选，支持单场景、拼图和宫格；产品可以不露出。
8. 三个功能拥有独立的任务类型、提示词、恢复路由和测试覆盖。

### 2.2 非目标

- 不增加 AI 质量评分、合规检测、结果自动重试或二次视觉审核。
- 不增加套图模板管理、历史套图项目管理或画布编辑。
- 不支持任意宽高比、具体像素尺寸或新的比例选项。
- 不增加中文或语言选择器；画面营销文字固定为英文。
- 不支持一次上传多个不同 SKU 并分别生成。
- 不改变现有“产品处理”中的主图裂变、场景裂变和创作新场景。

## 3. 方案选择

采用三个独立图片功能和一个独立套图页面：

| 功能 | Feature ID | 执行模式 | 必填图片角色 |
|---|---|---|---|
| 主图 | `product_main_image` | `edit` | `product` |
| 对比图 | `product_comparison_image` | `edit` | `product` |
| 多场景图 | `product_multi_scene` | `edit` | `product` |

没有采用复用旧 Feature 的方案，因为新需求与旧“主图裂变”“场景裂变”的输入、输出和恢复语义不同。也没有将三种模式合并为单个 Feature，以免在校验、提示词和任务展示中引入持续增长的模式分支。

每个 Feature 接受一张或多张 `product` 图片。多张图片必须属于同一个 SKU，可分别展示正面、侧面、包装和标签细节；应用不负责自动判断用户是否混入不同 SKU。

## 4. 页面与交互

### 4.1 导航与布局

- 侧边导航顺序为：贴纸出图、产品处理、套图处理、设置、个人中心。
- 套图页面使用当前产品处理工作区的视觉语言和结构，不新增独立设计系统。
- 顶部使用现有子 Tab 样式展示“主图”“对比图”“多场景图”。
- 左侧继续使用参考图、基础参数、进阶参数区。
- 底部继续使用现有生成按钮、提交状态和批次进度。
- 右侧继续使用任务抽屉、任务日志、结果预览、复制图片和打开目录能力。
- 切换子 Tab 时保留每个 Tab 各自的上传、输入、比例和数量状态。

### 4.2 表单

| Tab | 参考图 | 基础参数 | 进阶参数 |
|---|---|---|---|
| 主图 | SKU 产品图，必填，可多张 | 图片比例、生成数量 | 可选提示词、反向提示词、具体场景词、手持方式、具体效果 |
| 对比图 | SKU 产品图，必填，可多张 | 图片比例、生成数量 | 可选提示词、反向提示词、具体场景词、布局、After 产品展示、效果程度 |
| 多场景图 | SKU 产品图，必填，可多张 | 图片比例、生成数量 | 可选提示词、反向提示词、画面模式 |

图片比例使用现有 `AspectRatioSelect` 和默认值。生成数量使用现有 `ImageCountSelector` 和默认值，不增加手动输入。

### 4.3 生成数量语义

- 主图选择 N 张时，生成 N 张具有不同核心场景或主视觉构图的完整主图。
- 对比图选择 N 张时，生成 N 张单场景 Before/After 对比图；每张对应一个独立任务和结果。
- 多场景图选择 N 张时，生成 N 张不同的适用场景图；单场景模式每张只包含一个场景，拼图和宫格模式可包含多个场景。

## 5. 出图契约

### 5.1 共享 SKU 规则

- 模型综合参考全部 SKU 图片，将它们视为同一个产品的不同视角或细节。
- 输出中凡出现产品，必须保持产品形状、包装、品牌、标签、颜色和关键文字一致。
- 不得重新设计 SKU，不得替换品牌，不得虚构与参考图冲突的包装信息。
- SKU 图片用于识别产品用途和视觉身份，不要求在所有模式、所有结果中都露出。

### 5.2 主图

每张主图必须同时包含：

1. 对应的 SKU 产品。
2. AI 根据 SKU 自动生成的一条清晰英文大标题。
3. 一个能够表达核心用途或核心卖点的明确使用场景。

附加规则：

- AI 根据 SKU 自动识别产品类型、用途、核心卖点和最具代表性的场景，不要求用户填写标题。
- 产品是主视觉；标题必须清晰可读；场景元素用于支撑核心卖点，不堆叠无关装饰。
- 不生成中文营销文字。
- 同一批次多张结果应改变核心场景或主视觉构图，避免只做细微变化。

### 5.3 对比图

每张结果只包含一个场景的一组 Before/After。布局由 `comparisonLayout` 控制为自动、左右或上下。

附加规则：

- Before/After 保持相同环境、对象、视角、构图和光线，使变化可信且容易辨认。
- 使用清晰英文 `BEFORE` 和 `AFTER` 标识，不使用中文营销文字。
- Before 只展示使用前的问题状态，不展示 SKU。
- After 是否展示 SKU 由 `showProduct` 控制，并展示合理的改善效果。
- 不输出四阶段过程图。

### 5.4 多场景图

- 提示词用于补充产品适用场景方向，为可选项；为空时 AI 根据 SKU 发散真实适用场景。
- 画面模式可为单场景、拼图或宫格；单场景模式每张只展示一个完整场景。
- SKU 不强制露出；画面可以只表现适用环境、使用过程或使用效果。
- 即使 SKU 不露出，场景也必须符合从 SKU 识别出的真实用途。
- 同一批次的场景在地点、使用情境或视觉构图上应有明显差异，不能生成近似重复结果。
- 默认不添加标题、卖点或其他营销文字；用户在可选正向提示词中明确要求时才允许添加。

## 6. 请求模型与数据流

### 6.1 请求字段

三个 Feature 继续使用 `ImageTaskRequest`。为分批执行和准确恢复原始生成数量，增加两个通用可选字段：

```ts
interface ImageTaskRequest {
  variantIndex?: number;
  variantTotal?: number;
}
```

约束：

- `variantIndex` 和 `variantTotal` 必须同时存在或同时缺失。
- 二者必须为正整数。
- `variantIndex` 不得大于 `variantTotal`。
- 套图页面生成的请求始终携带这两个字段，序号从 1 开始。
- `variantTotal` 代表用户在生成数量选择器中选择的原始数量。

### 6.2 请求拆分

选择 N 张后，Renderer 组装 N 个 `count: 1` 的请求，通过 `useImageTask.submitMany()` 提交。所有请求共享同一 `outputBatchId`，并分别携带：

```text
variantIndex: 1..N
variantTotal: N
```

拆分请求而不使用单请求 `count: N`，以保持当前批量任务行为：

- 每张结果独立报告排队、运行、成功或失败状态。
- 批次部分失败时保留已经成功的结果。
- 同一批次产物写入共同目录。
- 提示词可以根据当前变体序号要求场景或构图差异。

### 6.3 提示词组装

三个 Feature 各自拥有独立 `mainPrompt`。`buildExecutionPrompt()` 在现有主提示词、用户提示词和结构化参数之外，追加自然语言变体说明：

```text
这是本批次第 {variantIndex}/{variantTotal} 张。生成与同批其他图片明显不同的场景或构图，同时遵守当前功能的全部固定规则。
```

三个 Tab 均可携带可选 `prompt` 与 `negativePrompt`；主图和对比图可携带 `scenePrompt`，多场景图携带 `multiSceneLayout`。提示词不能假设模型能看到同批其他任务，只通过当前序号要求差异，因此“避免重复”是生成约束而不是绝对去重保证。

### 6.4 数据流

```text
页面表单
  → 校验 SKU、比例和数量
  → 组装 N 个带变体序号的 ImageTaskRequest
  → useImageTask.submitMany()
  → Main Process 校验 Feature、product 图片和变体字段
  → 独立 mainPrompt + 结构化控制项 + 可选场景/正向/反向提示词 + 变体说明
  → 图片编辑模型
  → 同一批次本地目录
  → 任务抽屉展示独立进度和结果
```

## 7. 路由与任务恢复

视图类型增加：

```ts
type ActiveTab = 'sticker' | 'product' | 'productSet' | 'settings' | 'profile';
type ProductSetSubTab = 'main' | 'comparison' | 'multiScene';
```

`featureRoutes` 增加三个映射：

| Feature | 页面 | 子 Tab |
|---|---|---|
| `product_main_image` | `productSet` | `main` |
| `product_comparison_image` | `productSet` | `comparison` |
| `product_multi_scene` | `productSet` | `multiScene` |

从个人中心恢复任务时：

- 根据 Feature 打开套图页面及对应子 Tab。
- 从 `images` 中恢复全部 `product` 图片。
- 恢复 `aspectRatio`。
- 从 `variantTotal` 恢复生成数量；字段缺失时使用 1。
- 恢复三个 Tab 的可选正向/反向提示词及各自适用的结构化控制项；旧任务缺少字段时使用增强设计定义的默认值。
- 恢复当前任务和同批可查询任务的结果状态，沿用现有任务绑定方式。

`variantIndex` 只描述原任务在批次中的位置，不影响恢复后的下一次提交；用户重新生成时会根据当前数量创建一组新的连续序号。

## 8. 校验与错误处理

### 8.1 提交前校验

- 三个 Tab 没有 SKU 图片时阻止提交，提示“请上传 SKU 产品图”。
- 可选提示词为空或只包含空白时不阻止提交，提交时省略该字段。
- 图片文件格式、拖拽、粘贴和批量导入沿用 `ImageUploader` 的现有规则。
- 比例交给现有比例标准化与协议映射逻辑校验。
- 数量来自现有选项，并继续服从设置中的 `maxCount`。
- Main Process 再次校验必填图片角色和变体字段，不只信任 Renderer。

### 8.2 运行失败

- 提交失败和单任务出图失败沿用现有任务状态、错误与日志展示。
- 批次部分失败时不回滚成功结果，失败项在任务抽屉中单独显示。
- 每个任务继续保存 `request.json` 和 `image-instruction.txt`，用于核查图片输入、参数和最终提示词。
- 模型未严格遵守布局、英文标题、产品一致性或场景差异时，本阶段不自动重试；先通过可测试提示词契约和可审计产物保障基础质量。

## 9. 组件与模块边界

- 新增 `ProductImageSet` 页面组件，负责三个子 Tab 的表单状态、提交校验和请求组装。
- `ProductImageSet` 复用 `FeatureWorkspaceLayout`、`FeatureParameterPanels`、`ImageUploader`、`AspectRatioSelect`、`ImageCountSelector`、`GenerationTaskStatus` 和 `GenerationResult`。
- Feature 定义、角色校验和主提示词继续集中在图片领域模块，不放入页面组件。
- 套图任务恢复转换逻辑放在任务恢复功能目录，页面只消费转换后的状态。
- 不为三个结构相近的 Tab 分别创建完整页面；仅在存在可复用且能减少重复的局部表单时提取小组件。

## 10. 测试与验收

### 10.1 领域与提示词测试

- 三个 Feature 被 `IMAGE_FEATURES` 接受并路由到正确定义。
- 三个 Feature 都接受多张 `product` 图片，缺少 `product` 时拒绝请求。
- 三个 Feature 都使用 `edit` 执行模式，并把所有 `product` 图片传入执行模型。
- 主图提示词包含产品、AI 英文大标题和核心场景硬规则。
- 对比图提示词包含单场景 Before/After、自动/左右/上下布局、Before 不露产品、After 产品展示控制和英文标识规则。
- 多场景提示词包含单场景/拼图/宫格、产品可不露出和按 SKU 用途匹配规则。
- 三个 Tab 的可选正向、反向提示词及适用的具体场景词进入最终执行提示词。
- 变体序号进入最终执行提示词。
- 变体字段缺一、非正整数或越界时请求校验失败。

### 10.2 页面测试

- 侧边栏显示“套图处理”，点击后进入新页面，默认展示“主图”。
- 页面显示“主图”“对比图”“多场景图”三个子 Tab。
- 三个 Tab 都显示 SKU 上传、图片比例和生成数量。
- 三个 Tab 均显示可选正向和反向提示词，并显示各自适用的高级控制项。
- 缺少 SKU 时不提交；可选提示词为空时仍可提交。
- 选择 N 张时提交 N 个 `count: 1` 请求，序号为 `1..N`，总数均为 N。
- SKU 多张图片全部以 `product` 角色进入每个请求。
- 切换子 Tab 后各自状态保持不变。

### 10.3 恢复与回归测试

- 三种任务从个人中心恢复到正确页面和子 Tab。
- SKU 多图、比例、`variantTotal`、可选提示词和结构化控制项正确恢复。
- 缺少 `variantTotal` 的任务按数量 1 恢复。
- 现有贴纸出图和产品处理 Feature 路由保持不变。
- 现有任务列表、结果预览、复制图片和打开目录行为保持不变。

### 10.4 完整验证

1. 运行 `pnpm test`。
2. 运行 `pnpm lint`。
3. 运行 `pnpm build`。
4. 运行 `pnpm build:electron`。
5. 在具备有效模型配置时，每个新 Feature 至少执行一次真实冒烟任务。
6. 对照 `request.json` 和 `image-instruction.txt` 检查多 SKU 参考图、比例、变体序号、场景提示词和出图契约。

## 11. 完成标准

- 用户可从独立“套图处理”导航进入三个符合现有样式的出图 Tab。
- 三个 Tab 均能上传同一 SKU 的多张图片，并选择现有比例和生成数量。
- 主图每张都包含对应产品、AI 生成的英文大标题和核心场景。
- 对比图每张包含一个可信的 Before/After 场景，布局与 After 产品展示遵从结构化控制项。
- 多场景图在单场景、拼图或宫格模式下生成 N 张不同适用场景图片；提示词可选，不强制产品露出。
- 数量 N 对应 N 个独立任务和 N 张完整结果，并能从任务记录恢复原数量。
- 三个新 Feature 可独立显示、追踪、恢复和审计，不改变旧 Feature 行为。
- 自动化测试、类型检查、Renderer 构建和 Electron 构建通过；真实模型冒烟测试在具备有效凭据时完成。
