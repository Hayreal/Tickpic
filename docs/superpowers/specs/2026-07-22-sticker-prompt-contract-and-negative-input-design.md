# 贴纸提示词契约与负面提示词输入设计

**日期：** 2026-07-22

**状态：** 已完成方案讨论，等待书面设计复核

**范围：** 贴纸复刻、贴纸裂变、贴纸原创的 UI、任务数据和最终出图提示词

## 1. 背景

当前贴纸提示词分散在功能 `mainPrompt`、通用结构化参数拼接和执行后缀中。实际出图反馈包括：

- 标签未按瓶身正面可贴区域形成协调的平面比例和内容密度。
- 贴纸裂变结果仍会带出瓶、罐等产品主体。
- 标题、品牌、卖点、副标题、容量和装饰元素可能缺失、拥挤或乱码。
- 品牌展示、注册标识、品牌颜色和 Logo 形态缺少统一约束。
- 用户需要自行指定不得出现的文字、元素或效果，现有界面没有独立入口。

本次改造建立集中式贴纸提示词契约，并为三个贴纸模式新增可恢复的多行负面提示词输入。

## 2. 目标与非目标

### 2.1 目标

1. 三个贴纸模式使用同一套不可被低优先级内容覆盖的输出硬规则。
2. 复刻、裂变和原创分别拥有明确的保留项、变化项和参考图角色。
3. 品牌使用用户输入并追加 `®`；品牌为空时使用 `wkau®`；可见品牌为纯白文字，不设计额外图形 Logo。
4. 容量只去除首尾空白后原样进入提示词，不换算单位、不补数值、不规范化格式。
5. 输出仅包含一张正视二维平面标签，不出现产品、容器、场景、展示背景或 3D mockup。
6. 标签根据瓶身正面可贴区域和目标画布组织协调的平面比例、留白与内容密度。
7. 三个模式分别提供多行“负面提示词”，随任务持久化并在恢复任务时原样回填。
8. 负面提示词作为用户自定义禁用项进入最终提示词；系统不维护违禁营销词表，也不自动改写用户文案。
9. 非贴纸功能的提示词行为保持不变。

### 2.2 非目标

- 不新增 OCR、广告法审核服务或独立内容审核 API。
- 不自动识别、替换或规范化违禁营销词。
- 不改变现有图片比例控件、尺寸计算或图片模型 API 参数。
- 不调用图片模型生成验收图。
- 不把平面标签输出扩展为瓶贴预览、包装效果图或 3D 渲染。

## 3. UI 设计

### 3.1 字段位置与形态

贴纸复刻、贴纸裂变和贴纸原创的高级参数区域分别新增多行文本框：

- 标签：`负面提示词`
- 默认值：空字符串
- 占据完整表单宽度
- 位置：现有附加提示词附近
- 占位文案：`输入不希望图片中出现的文字、元素或效果；支持多行`
- 辅助示例：`例如：禁止 BEST、NO.1、100%；不要医疗功效词；不要金色渐变。`

三个模式分别维护输入状态，切换模式时互不覆盖。用户不必重复填写系统已有的“不要产品、容器、场景或 3D mockup”等硬规则。

### 3.2 提交与恢复

`ImageTaskRequest` 新增可选字段：

```ts
negativePrompt?: string;
```

提交任务时仅在去除首尾空白后仍有内容时携带该字段。任务记录沿用现有请求 JSON 持久化机制，不新增存储表。

`applyStickerRestore()` 为三个模式分别返回对应的负面提示词状态；恢复历史任务时：

- 请求中包含该字段的任务：回填原始 `negativePrompt`。
- 旧任务：字段不存在时回填空字符串。
- 字段内容不拆分、不改写，换行原样保留。

## 4. 提示词架构

### 4.1 集中式构建器

新增贴纸专用提示词构建模块，由 `buildExecutionPrompt()` 在 `sticker_replica`、`sticker_variation` 和 `sticker_original` 三种功能下调用。非贴纸功能继续使用现有通用拼接流程。

贴纸最终提示词按固定顺序组装：

1. 共享硬性输出契约。
2. 当前模式契约。
3. 当前裂变方向契约，仅裂变使用。
4. 品牌、容量、产品名称、卖点、素材、色系、风格和色块排版等结构化字段。
5. 参考图角色说明。
6. 用户附加提示词。
7. 用户负面提示词。
8. 失败条件与最终自检。

优先级固定为：

```text
系统硬规则
> 模式规则
> 结构化字段与参考图规则
> 用户附加提示词
> 用户负面提示词
```

用户附加提示词或负面提示词与系统硬规则冲突时，系统硬规则优先。负面提示词不得用于要求输出产品、场景或 3D 包装。

### 4.2 共享硬规则

三个贴纸模式都必须要求模型：

- 只输出一张独立、正视、高完成度的二维平面标签。
- 禁止瓶、罐、盒、产品主体、包装容器、手持、使用场景、展示台、额外背景、拼贴和 3D mockup。
- 标签完整居中，四边留出明确安全空间，不贴边、不裁切。
- 外轮廓为直角矩形，边缘水平或垂直；不输出圆角、弧边、异形、模切边或瓶身弧面轮廓。
- 根据源图中瓶身正面可贴区域与目标画布比例，推断协调的平面标签宽高关系、视觉重心和内容密度；不沿用拍摄透视或容器曲率。
- 标签中的标题、品牌、卖点、副标题、容量和装饰图形完整存在。
- 所有可见文字采用英文电商标签的阅读层级，清晰、正确、无乱码、无随机字符、无拥挤变形。
- 参考图文字过长时根据英文长度调整字号、行数和间距，保持平衡，不强行挤压。
- 主标题相对于参考图常见占比缩小约 20%，继续居中并保持可读性。
- 整体呈现高完成度、高相似度或明确的同系列关系，以及可用于贴纸设计参考的商业质感。

### 4.3 品牌与容量

品牌规则：

- 使用 `request.brand` 去除首尾空白后的值。
- 品牌为空时使用 `wkau`。
- 最终可见品牌只追加一次 `®`；输入已经包含 `®` 时不重复追加。
- 品牌为纯白文字，不设计图形 Logo、徽记或额外品牌符号。
- 单独 Logo 图片只用于识别品牌位置或文字，不作为版式、色系和风格参考；最终仍遵守纯白文字规则。

容量规则：

- 使用 `request.capacity` 去除首尾空白后的原始字符串。
- 不换算 ML、FL.OZ、G、OZ 或其他单位。
- 不补全缺失单位或生成额外数值。
- 不改变大小写、标点、内部空格或用户提供的数值格式。
- 仅要求模型将该字符串作为容量文案清晰排版。

### 4.4 用户负面提示词

当 `negativePrompt` 非空时，最终提示词新增独立区块：

```text
用户指定的禁止项（不得出现在最终图片中）：
<用户输入，保留换行>
```

系统不解释、拆分、翻译、扩写或自动改写该文本。该区块是自然语言提示的一部分，不映射为独立图片 API 参数。

## 5. 模式契约

### 5.1 贴纸复刻

复刻模式要求：

- 保留源贴纸的视觉语言、色系、图形、信息层级和元素相对位置。
- 将侧拍、斜拍和弧面内容去透视并展平，补全绕到侧面或被曲面压缩的信息。
- 以瓶身正面可贴区域为判断依据，形成协调的完整平面标签，而不是复制瓶身轮廓或拍摄透视。
- 按共享规则替换品牌展示，容量保持用户输入原样。
- 单独 Logo 图不作为布局、配色或风格参考。

### 5.2 贴纸裂变

裂变模式要求：

- 保留品牌、品类识别、核心卖点和同系列商业质感。
- 严格按用户选择的裂变方向改变布局、色块、视觉重心、背景结构或重点元素。
- 移除与具体裂变方向冲突的通用“必须明显改变版式”执行后缀。例如换色裂变可以保留布局，不能再被通用后缀强制大改。
- 输入图即使包含完整产品，也只提取标签设计信息；最终结果不得出现产品或容器。

### 5.3 贴纸原创

原创模式要求：

- 根据品牌、品类、产品名称、卖点、素材、容量、色系、风格和版式字段建立完整英文电商标签。
- 参考图只指导视觉风格和设计语言，不复制其品牌或产品主体。
- 不凭空增加用户未提供的绝对化功效承诺。
- 输出仍只是一张正视二维平面标签。

## 6. 失败条件与自检

最终提示词要求模型在输出前检查以下失败条件：

- 出现瓶、罐、盒、产品、包装展示、手持、场景、背景或 3D mockup。
- 标签不是正视平面图，仍包含容器透视、曲率、侧面、厚度、阴影或反光。
- 标签未居中、四边无安全留白、边缘被裁切或整体透明。
- 品牌未追加 `®`、重复追加 `®`、不是纯白文字或被设计成图形 Logo。
- 容量被换算、补全或改写。
- 标题、品牌、卖点、副标题、容量或关键装饰图形缺失。
- 出现中文、乱码、拼写错误、随机字符、文字拥挤或不可读微缩字。
- 用户负面提示词中列出的文字、元素或效果仍然出现。

## 7. 测试策略

### 7.1 领域与请求测试

- `ImageTaskRequest` 接受可选 `negativePrompt`。
- 请求清理逻辑保留非空负面提示词并忽略纯空白值。
- 非贴纸请求不会意外拼接贴纸负面提示词区块。

### 7.2 UI 与恢复测试

- 三个贴纸模式均渲染多行负面提示词输入框。
- 三个输入状态互不覆盖。
- 提交请求携带当前模式的 `negativePrompt`。
- 恢复三个模式任务时分别回填原值。
- 恢复没有该字段的旧任务时回填空字符串。

### 7.3 提示词测试

- 三种模式都包含共享平面标签输出契约。
- 三种模式都明确禁止产品、容器、场景和 3D mockup。
- 裂变输入产品图时仍明确只输出标签。
- 三种模式分别包含正确的模式契约。
- 每个裂变方向不再被冲突的通用大改后缀覆盖。
- 默认品牌生成 `wkau®`，自定义品牌只追加一次 `®`。
- 品牌纯白文字、无图形 Logo 的规则存在。
- 容量字符串逐字保留，不生成换算说明。
- 非空负面提示词以独立禁止项区块保留换行进入最终提示词。
- 纯空白负面提示词不生成空区块。
- 用户附加要求出现在硬规则之后，并明确不能覆盖硬规则。
- 非贴纸功能现有提示词快照保持不变。

## 8. 文档与验收

更新 `docs/ai-image-system-prompts.md`，记录贴纸专用构建路径、负面提示词字段和最终组装顺序。

本次不调用图片模型。完成标准是：

1. 类型检查、相关单元测试和全量测试通过。
2. 三个模式的 UI、提交和恢复链路完整。
3. 最终提示词测试覆盖截图要求和新增负面提示词行为。
4. 非贴纸功能没有行为回归。
