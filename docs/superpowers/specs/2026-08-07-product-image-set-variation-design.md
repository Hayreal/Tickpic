# 套图批次差异化与纯场景输出设计

**日期：** 2026-08-07

## 1. 背景

套图处理目前把每张输出拆成独立任务，并通过 `variantIndex` 和 `variantTotal` 告诉模型当前批次位置。但现有变体提示词只要求“与同批其他图片明显不同”，没有为当前任务指定具体差异方向。模型无法看到同批其他结果，容易生成场景、构图和风格相近的主图、对比图和多场景图。

当前多场景图还允许 SKU 出现，也没有禁止人物或手部，无法稳定输出只包含目标环境的纯场景素材。

## 2. 目标

- 同一批次的每张主图、对比图和多场景图获得明确、不同的变体方向。
- 用户填写目标场景后，在同类场景范围内变化，不偏离用户主题。
- 多场景图仅输出目标场景，不出现 SKU、产品包装、人物、手部或人物使用动作。
- 不新增 UI 字段、请求字段、模型调用或任务阶段。

## 3. 非目标

- 不让模型读取同批其他任务的生成结果。
- 不增加批次规划模型调用或自动重试。
- 不改变主图的手持控制；“禁止人物”仅适用于多场景图。
- 不改变对比图现有的中央前景 SKU、布局和效果强度规则。
- 不保证模型百分之百服从视觉差异，只提供明确且可测试的提示词契约。

## 4. 差异化机制

每个产品套图请求继续携带 `variantIndex` 和 `variantTotal`。执行提示词根据当前 Feature 和变体序号生成具体方向，不再只使用统一的“明显不同”描述。

每个方向至少指定以下差异维度中的三个：

- 目标子场景或空间位置。
- 主体对象或问题区域。
- 构图重心和元素层次。
- 机位、景别或观察角度。
- 光线方向、时间氛围或明暗关系。
- 视觉风格和背景表达。

不得把轻微换色、只改标题、只移动产品或只更换装饰物视为有效差异。

### 4.1 方向循环

当前默认数量为主图 3 张、对比图 3 张、多场景图 2 张，因此定义前三个稳定方向：

1. **核心方向：** 最典型的目标场景，平衡构图，清晰商业光线，直接表达核心用途。
2. **环境方向：** 同类场景中的不同子空间或使用位置，改变机位、景别和光线方向。
3. **视觉方向：** 同类场景中的另一种环境表达，改变构图重心、背景层次和视觉风格。

若未来批次数量超过 3，按序号循环方向，并要求在循环内进一步改变具体子场景和构图，避免逐字复用同一方向。

## 5. 用户场景词

用户提供 `scenePrompt` 时，所有变体必须保持在该目标场景的语义范围内，通过子场景、对象、空间位置、构图、机位和光线产生差异。

例如用户填写“浴室瓷砖”：

- 可以使用淋浴区墙砖、洗手台附近瓷砖、浴缸周边瓷砖等子场景。
- 可以改变近景、俯视、正视、侧向机位和光线方向。
- 不得扩展到厨房、客厅或其他无关场景。

用户未提供场景词时，模型根据 SKU 品类选择相互明显不同但真实适用的目标场景。

## 6. 主图规则

- 每张必须展示输入 SKU，并保持形状、包装、品牌、标签、颜色和关键文字一致。
- 每张执行对应的变体方向，改变目标子场景、构图、机位、光线和视觉表达。
- 继续服从 `productHandheldMode` 和 `productEffectMode`。
- 人物或手部是否出现仍由现有手持控制决定。
- 不得只换色、只换标题、轻微移动产品或仅修改装饰元素。

## 7. 对比图规则

- 每张内部继续保持 Before/After 的同一场景、对象、机位、尺度、构图、光线、材质和结构。
- 不同图片之间改变同类目标场景的子区域、问题对象、整体构图和视觉表达。
- 每张只包含一个场景和一组 Before/After。
- 继续服从布局、效果强度和产品展示控制。
- `showProduct=true` 时继续只显示一个跨中央分界线的独立前景 SKU。
- 不得通过破坏单张图内部的一致性来制造批次差异。

## 8. 多场景图规则

输入 SKU 只用于识别产品品类、用途和适用环境，不作为输出画面中的可见对象。

所有多场景输出必须满足：

- 不出现 SKU 或输入产品。
- 不出现产品包装、品牌瓶罐或其他可识别商品实例。
- 不出现人物、人体、面部、手部、手持动作或人物使用动作。
- 只展示具体目标场景、目标对象、表面、空间或环境状态。
- 默认不添加标题、卖点或营销文字，除非用户明确要求且不违反前述硬规则。

布局差异：

- `single`：每张只展示一个完整目标场景；批次内每张使用不同子场景和构图。
- `collage`：每张组合一组不同目标场景，各区域边界清晰；不同输出不得复用同一组场景。
- `grid`：每张使用规则网格展示一组不同目标场景；不同输出不得复用同一组场景。

## 9. 提示词组装

产品套图执行提示词按以下顺序组装：

1. Feature 基础主提示词。
2. Feature 结构化控制项。
3. 结构化业务参数。
4. Feature/场景范围硬规则：主图和对比图使用精确 `scenePrompt` 范围规则或未指定场景回退；多场景图使用条件场景规则。
5. 冲突优先级规则。
6. 用户场景词、补充要求和反向要求。
7. Feature 与变体序号对应的差异化方向。
8. 英文可见文字规则。

Feature/场景范围规则属于硬约束，必须位于冲突优先级规则之前。多场景图的禁产品、禁人物规则同样属于功能硬规则，优先于用户补充要求。用户要求在多场景图中加入人物、手部或产品时必须忽略冲突部分。

## 10. 测试

提示词测试覆盖：

- 三个 Feature 的第 1、2、3 个变体获得不同方向。
- 主图变体明确改变子场景、构图、机位、光线或视觉表达。
- 对比图变体差异不会破坏单张 Before/After 内部一致性。
- 有场景词时明确要求在同类场景内变化，不扩展到无关场景。
- 无场景词时允许选择不同的真实适用场景。
- 多场景图明确禁止 SKU、商品包装、品牌瓶罐、人物、人体、面部、手部和人物使用动作。
- 多场景图的单场景、拼图和宫格模式分别包含批次差异要求。
- 用户补充要求与多场景硬规则冲突时，冲突优先级规则位于用户文本之前。
- 没有完整变体字段时不追加差异化方向。

## 11. 验收标准

- 默认 3 张主图分别携带三个明确且不同的生成方向。
- 默认 3 张对比图分别携带三个明确且不同的批次方向，同时每张内部保持 Before/After 一致性。
- 默认 2 张多场景图携带不同目标子场景和构图方向。
- 多场景图最终执行提示词明确禁止产品和人物相关内容。
- 用户指定场景后，差异化仍保持在指定场景的同类范围内。
- UI、请求结构、任务拆分和模型调用次数保持不变。
