# 套图自然语言执行提示词设计

日期：2026-08-27

## 目标

主图、对比图和多场景图发送给图片模型的执行提示词改为简洁自然语言。JSON 只保留在视觉规划和内部规格数据中，不出现在 image-instruction.txt 或 execution-prompt-N.txt。

规则必须通用：只描述产品、实际使用对象和可观察状态之间的自然关系，不固定某类污渍、道具、台面或使用地点。

## 方案

内部规格继续承担 SKU 锁定、UI 控制、视觉规划结果和批次差异。文本渲染器从规格中选择当前 feature 和当前变体真正需要的内容，按以下顺序生成短段落：

1. 输出目标、画幅和电商视觉风格。
2. SKU 身份锁定：包装、比例、材质、标签和标签相对执行端的位置。
3. feature 专属画面关系。
4. 当前视觉规划给出的地点、目标对象/状态、构图和变体方向。
5. 英文可见文字、用户补充和用户避让要求。

同一约束不重复写入多个段落，也不追加第二份变体或批次清单。

## Feature 语义

主图：需要场景时，产品、实际使用对象和可观察状态构成一张连贯照片。准备图不虚构动作，但目标状态可见；效果图的真实执行端朝向并作用于目标对象。手持和参考姿势仅在当前变体实际要求时出现。

对比图：Before 和 After 是可验证的对应证据。产品展示开启时，产品是一层合理的前景包装主体，不能遮住证据，也不能引入只为摆放产品或填充画面而存在的支撑面、道具或陈列环境。可选布局为左右、上下、2x2 和 3x2；自动模式按批次变体稳定轮换，手动布局优先。

多场景图：保持单场景、拼图和六宫格的原有用途；只渲染当前布局需要的规则，且不渲染 SKU 本体或人物。

## 执行器边界

执行器不再从最终提示词解析 JSON。提示词构建函数将每张文本与 requiresHandheldReference 元数据一起返回，执行器据此决定是否附带手持参考图。视觉规划 JSON 继续作为调试包的一部分。

## 验收

- 最终套图提示词不以左花括号开头，不含 JSON 字段名或 VARIANT DIRECTIVE。
- 三类 feature 均保留必要的产品锁定和布局控制。
- 自动对比布局在四张连续变体中依次使用四个不同布局。
- 非手持变体不传入手持参考图。
